## ⭐ 先判你的卡能不能解（5 秒无损判别，装之前必看）

同样是华硕 CMP 40HX（同一套设备 ID `10DE:1F0B / 1043:8804`），出厂却有**两个 VBIOS 固件分支**，
能不能解锁完全由它决定（2026-10-11 三张实卡 VBIOS 逐字节对比 + 开机固件日志实证）：

| 你的 VBIOS 版本 | 固件分支 | 算力（SS0） | PCIe Gen2 | 结论 |
|---|---|---|---|---|
| **90.06.67.00.04** | NVPartner **Debug** 签名链 | ✅ 可解 | ✅ 可解 | **适用本包，直接装** |
| **90.06.67.00.06** | 已知流通变体多为 NVPartner **Prod** 签名链（⚠️ .06 存在多个内容变体，已实测到内容互异的个体） | ⚠️ 因变体而异：2 例固件拒签、四条引导路径全灭；**1 例（2026-10-12 客户机）算力+Gen2 全部解锁成功** | ⚠️ 视机器：Windows 侧工具可独立落地（不依赖固件） | **别看到 .06 就放弃**：最终判定看安装器批次预检/`一键诊断.cmd`（已有成功先例，先装先试）；确认无解再考虑刷 Debug 版 VBIOS（高风险） |
| 其它版本 / 其它品牌 | 未收录 | 以实测为准 | 以实测为准 | 跑一遍 `一键诊断.cmd` 把报告发给作者 |

**怎么查自己的 VBIOS 版本**（无损、不碰硬件，三选一）：

1. 装好 NVIDIA 驱动后，CMD 里跑 `nvidia-smi -q | findstr "VBIOS"`；
2. 双击一键包里的 **`状态自检.bat`**（已内置该判别，会直接写结论）；
3. 双击 **`一键诊断.cmd`**（诊断报告里带 VBIOS 版本与批次判定）。

**三个别踩的坑**：
- **序列号号段不能当判别依据**（实测相近号段混刷两种分支）——先看 VBIOS 版本号，落在 .06 再靠诊断定变体；
- **版本号相同的 .06 镜像内容也可能不同**（实测两份 .06 dump 的 MD5 互不相同、与 TechPowerUp 公开 .06 也不同）——所以 .06 的最终判定以"实际写入是否生效"为准：本包安装器在写 EFI 前会做只读批次预检（POST 寄存器形态），诊断包也会采集；
- Prod 批次别指望"换个软件/换个驱动就能解算力"：注入在开机固件阶段就被签名链拒绝了，Windows 侧没有任何手段补救（PLM 关窗后寄存器只读）。
- **.06 已有解开算力的先例**（2026-10-12 客户机，技嘉 Z370 平台）：同一版本号下确实存在能解的变体。正确姿势是**先装本包跑一遍**（开机看有没有 40HX 跑码界面、`40hx_log.txt` 有没有 `UNLOCKED`），别看到 .06 就放弃；反过来也别拿别人的成功案例当保证，以自己机器的实测为准。

**Prod 批次的算力补救**（先跑一遍本包，确认你的 .06 不属于能解的变体之后再看这条）：对确认无解的卡，出路是把 VBIOS 刷成 Debug 版（90.06.67.00.04）。
刷显卡固件是**高风险操作**（中途断电/死机 = 变砖，需要编程器救卡；序列号区域会变成供体卡的），
必须用带**多源备份 + 一键回滚**的刷机包并严格按流程走 —— 联系作者获取。风险细节见 [`oneclick/文档/风险与恢复.md`](oneclick/文档/风险与恢复.md)。

## 〇、开装之前：BIOS 设置（已按紧要程度排序，脚本替你做不了）

> 现场"装完没效果 / 认不到卡 / 代码 43"绝大多数栽在这里。各家 BIOS 菜单名不一样，按**关键词**找
> （很多 BIOS 支持直接搜 `Secure Boot` / `4G` / `CSM` / `Fast Boot`）。

| 紧要程度 | 改什么（常见叫法） | 设成 | 不改会怎样 | 常见位置 |
|---|---|---|---|---|
| **1 · 必须（硬门槛）** | **Secure Boot**（安全启动） | **Disabled**（华硕老 BIOS 选 `Other OS`） | 解锁固件 `40HXUNLK.EFI` 是**未签名**的，Secure Boot 开着它就不执行 → 算力一直未解锁 | `Security → Secure Boot` |
| **2 · 装后必验证** | 启动顺序：**`40HX Unlock` 必须真被执行** | 排到第一位（装完第一次开机验证） | **脚本写进 NVRAM 的启动顺序 ≠ BIOS 里真的选了它**（2026-10-08 客户机实证：NVRAM 全对、固件照样不执行）。判据：第一次开机**没出现 40HX 跑码界面**（屏幕上先刷几行解锁固件文字再进 Windows）= 固件没被执行 → 进 BIOS 把它排第一，改完立刻解锁 | `Boot` 启动顺序列表 |
| **3 · 失败排查首查** | **Above 4G Decoding**（4G 以上解码 / 大地址解码） | 建议 **Enabled**（主板没这选项可跳过） | 多数单卡主机不开也能正常解锁（实测）；多卡/板载设备多的机器 4G 以下地址空间不够分时，关着会认不到卡、"代码 43"、甚至开机黑屏 | 华硕/ROG：`Advanced → System Agent (SA) Configuration`；技嘉：`Settings → IO Ports`；微星：`Settings → Advanced → PCI Subsystem Settings`（矿版叫 `Above 4G memory/Crypto Currency mining`）；华擎：`Advanced → Chipset Configuration` |
| **4 · 强烈建议** | **CSM**（Launch CSM / 兼容性支持模块） | **Disabled** | 开着、但系统确实是 UEFI+GPT 引导的也能正常解锁；害处是容易把系统装成 Legacy/MBR（那种会被判"固件不是 UEFI 模式"直接中止）；且开着 CSM 通常也开不了 Above 4G | `Boot → CSM` |
| **5 · 建议** | **Fast Boot**（快速启动） | **Disabled** | 部分固件（Ultra Fast 类）会跳过启动顺序直接进 Windows → 解锁固件那次开机没被执行；排查"没出现跑码界面"时必查。Windows 的"快速启动"（混合关机）是另一回事，也要关，安装器会自动关它 | `Boot → Fast Boot` |
| **6 · 只影响 Gen2** | 该 x16 槽的 **PCIe 速率**（PCIe Speed / Link Speed） | **Auto**（别锁 Gen1） | 锁在 Gen1 就永远上不了 **Gen2 x16**；设 Gen3/Gen4 也行（自动协商到 Gen2）。不影响算力解锁——纯算力可不管这项 | `Advanced`/`Chipset` 里的 PCIe 速率项 |

**同一时间顺手确认这几条（不在 BIOS 里，但同样决定成败）**：

| 项 | 要求 |
|---|---|
| 系统盘 | **GPT + UEFI**（老盘是 MBR：管理员执行 `mbr2gpt /convert /allowFullOS`） |
| BitLocker | 关掉或暂停（否则改引导链会索要恢复密钥） |
| 显示器接哪 | 40HX **没有视频输出口**：显示器接核显或另一张卡，BIOS 主显示设 `Auto` / `IGFX` 即可 |
| 杀软 | 火绒/360：既要在"信任区"放行三个驱动，**也要单独关掉"漏洞驱动拦截"**（它是独立模块，只加信任区不生效） |

> 想先只看不改：`oneclick/Install-40HXUnlock.ps1 -Mode Check`（纯体检，0 项失败 = 环境 OK）。
> BIOS 相关的逐条报错对照在 [`oneclick/排查指引.md`](oneclick/排查指引.md) 第 3 节（退出码 2）。

## 一、我要怎么做（只用 `oneclick/` 这一个文件夹）

1. 下载本仓库里的 **`oneclick/`** 文件夹（或 Releases 里的 zip），拷到那台装 40HX 的 Windows 上
2. 双击 **`一键安装.cmd`** → 回车（脚本自己申请管理员）→ 等它跑完（首次约 1 分钟）
3. **完全关机再开机**：开始菜单 → 关机（**不是"重启"**），最好拔掉电源线等 10 秒。
   开机时会先闪过一段解锁固件的跑码界面，然后才进 Windows；
   进 Windows 后双击 **`状态自检.bat`**，看到 `全绿 -- WDDM + PCIe Gen2 + 算力满血` = 成功。
   若看到黄字「未实测」**别慌**（黄 ≠ 失败）：开机后台任务还要跑 1 到 3 分钟，**过 2 到 3 分钟再双击一次**就会出结论。

出问题：`oneclick/排查指引.md`（按日志原话/退出码搜）；装完黑屏或设备管理器**代码 43** → **双击包根 `GSP体检.cmd`**（代码 43 最常见的根因就是 GSP 没开；它默认就会把开关写好，写完**完全关机**再开机），要取证再跑 `oneclick/工具-测试与修复/诊断包-20260930/一键诊断.cmd`；

## 四、这套方案的两条硬事实（决定你怎么排错）

1. **算力解锁是易失的**：每次开机由 ESP 上的固件写 GPU 寄存器（SS0=0x88888888）。
   所以"上次好的、这次不行"通常等于**这次开机固件没跑**（看 `40hx_log.txt` 的时间戳）。
2. **PCIe Gen2 靠 Windows 侧在驱动 bind 之后落地**：固件只预埋策略寄存器，重训由开机任务完成。
   而且**不能复位显卡**（复位就清算力）—— 这就是本方案选用 OnlyEFI 固件 + 只重训不复位的原因。

判据（别信 `nvidia-smi pcie.link.gen.current`，空闲恒显示 1）：
- 算力：ESP `40hx_log.txt` 有 `*** UNLOCKED (SS0=0x88888888 SS1=0x8) ***`（时间戳=本次开机）
- Gen2：`工具-测试与修复` 的日志里 `GPU final: Gen2 x16 LNKSTA=0x1102` / `ROOT final: ... 0xF102`，或 `OpenCL.exe` 基准标注 `PCIe Bandwidth (bidirectional) (Gen2 x16)`

## 五、免责声明

解锁涉及**改引导链、注册内核驱动、写固件启动项**，有变砖风险（仓库里提供了备份与回滚，见 `oneclick/文档/风险与恢复.md`）。
只在 **CMP 40HX（`10DE:1F0B`）** 上实测过；矿卡本身可能有暗病（例如 PCIe 延长线场景会出 `0x124` WHEA 硬件错误，与解锁无关）。
**VBIOS 批次限制（2026-10-11 实证）**：已知多数流通的 VBIOS `90.06.67.00.06` 变体（出厂 `Prod` 签名链）算力无法通过软件解锁
（开机注入被固件拒签）；但 .06 存在多个内容变体，**2026-10-12 已有一例 .06 实卡（Z370 平台）算力+Gen2 全部解锁成功**，
是否可解以你机器的实际安装结果（批次预检 / `一键诊断.cmd`）为准。确认无解的卡，唯一救法是刷写 `Debug` 版 VBIOS，
而刷固件本身是高风险操作（断电变砖、需编程器救卡），务必使用带备份与回滚的刷机包并自行权衡。
解锁行为可能违反 NVIDIA/游戏厂商服务条款，**请自行判断用途**。
